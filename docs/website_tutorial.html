How the SPIN Lab website works

A picture book for future you. Every chapter starts with a “like I'm five” idea, then shows how it really works in this site, with the exact files to open. This page lives in docs/, which Jekyll skips, so it is never published.

1What is a website?

A website is a pile of letters (files) sitting in a post office (a server). When you type the address, your browser asks the post office for the letters, then reads them out loud as a picture you can see and click.

Our site is a static website: the server just hands over ready-made files. Nothing is computed on the server when someone visits. That's why it can live for free on GitHub Pages at spinlabiitg.github.io.

2The kitchen: Jekyll

Writing every page by hand is like making every sandwich from scratch. Jekyll is a kitchen robot. You give it ingredients (your text, a list of people, photos) and lunchbox shapes (layouts), and it packs a finished lunchbox (an HTML page) for every page.

Jekyll is a program written in Ruby. The Gemfile lists the Ruby packages (“gems”) it needs, and Gemfile.lock pins their exact versions so everyone gets the same kitchen. Bundler is the tool that installs those gems; that's why commands start with bundle exec.

On GitHub, Pages runs Jekyll for you each time you push. On your computer, bundle exec jekyll serve does the same and also starts a little local server so you can preview at http://localhost:4000.

The two kitchens are not identical. This repo has no GitHub Actions workflow, so GitHub Pages builds with its own standard Jekyll (3.x, in “safe mode”), while your computer uses Jekyll 4.2.2 from Gemfile.lock. Safe mode ignores anything in _plugins/ (there's an unused markdown.rb there). Stick to plain Liquid, layouts, includes and data files, as this site does, and both kitchens cook the same meal.

4How one page is put together

Pages are like Russian nesting dolls. The biggest doll (the outer layout) holds a middle doll (the page layout), which holds the smallest doll (your page's words). Some parts, like the menu, are stickers stuck onto the big doll so every page gets the same one.

The top of every page file has a little label between --- lines, called front matter. It tells Jekyll which doll to use:

# _pages/showcase.md
---
title: "SPIN Lab - Showcase"   # shown in the browser tab
layout: textlay                 # which middle doll
permalink: /showcase/           # the web address
---

Open _layouts/textlay.html. It's only four lines! It says “use default, and put the page's words in a full-width column”.

5Liquid: fill in the blanks

A layout is a colouring page with blank spaces. Liquid is the instruction “write the name here” or “do this once for every friend in the list”. One cookie cutter, many cookies.

Two kinds of curly brackets, and that's most of Liquid:

WriteMeansExample in this site
{{ … }}Print a value here{{ t.title }} prints a theme's title
{% … %}Do something (loop, if, include){% for t in site.data.research %}
| filterChange a value on the way{{ t.body | markdownify }} turns *stars* into italics
{% include x.html %}Paste a sticker from _includes/{% include member_card.html m=m %}
<!-- _pages/home.md: one tile per research theme -->
{% for t in site.data.research %}
  <a class="theme-tile" href="/research/#{{ t.id }}">
    <img src="/images/{{ t.image }}">
    <b>{% include bi.html en=t.title hi=t.title_hi %}</b>
  </a>
{% endfor %}

site.data.research means “the file _data/research.yml”. Every file in _data/ becomes site.data.<filename> automatically.

6Data files: index cards

A data file is a box of index cards. Each card starts with a dash and says things like “name: Ashita”, “photo: ashita.jpg”. The pages read the cards and draw them nicely. To add a person you just write a new card.

The cards are written in YAML. Three rules cover almost everything:

  1. A dash starts a new card; lines under it are indented by two spaces.
  2. Spaces matter. Use spaces, never tabs.
  3. If a value contains a colon followed by a space, wrap it in quotes.
# _data/bachs.yml (BTech students)
- name: Shourya Goyal
  photo: shourya_goyal_btp_2026.jpeg
  topic: "Audio QR codes: generation, analysis and deployment"   # quotes because of ": "

- name: Srijan Kumar
  photo: srijan_btp_2026.jpg
  topic: Multimodal learning across music and dance

We actually hit rule 3 while building this: a Hindi line with “पाठ्यक्रम: ध्वनि…” broke the whole build with mapping values are not allowed in this context. Quotes fixed it.

7Styles: the clothes

HTML is the body; CSS is the clothes. The same body can wear a big coat on a computer and a small t-shirt on a phone. CSS rules say “if the screen is small, wear the t-shirt”.

css/main.scss is written in SCSS, which is CSS plus handy extras (variables like $brand-primary, and “mixins”, which are reusable bundles of rules). Jekyll turns it into plain css/main.css. The file has three layers:

  1. @import "bootstrap"; brings in Bootstrap 3: the grid (col-sm-8), buttons, the navbar.
  2. The original site's small tweaks.
  3. Our redesign, in clearly titled blocks: Refined layout, Showcase, Language switch, Dark mode, Signal hero, Say hey, Affiliation signature…

Most new layouts use CSS grid: grid-template-columns: repeat(3, 1fr) means “three equal columns”, and a @media (max-width: 767px) rule below it switches to one column on phones.

In your browser, right-click any card on the site → Inspect. You'll see its class (e.g. theme-tile). Search main.scss for that name to find its clothes.

8Night mode

The page has a light switch. When it's flipped, the page puts on its pyjamas: dark background, light text. If you never touch the switch, the page copies your computer's own day/night setting.

How the pieces fit:

  • The switch: the ☾/☀ button in _includes/header.html. Its click code is at the bottom of _includes/footer.html.
  • No flash: a tiny script at the top of _includes/head.html re-applies the saved choice before the page paints.
  • The pyjamas: in main.scss, @mixin dark-theme { … } lists every dark colour once, and is used twice: for html[data-theme="dark"] (switch flipped) and inside @media (prefers-color-scheme: dark) (computer is in dark mode and the switch was never touched).
  • Colours as variables: the moving picture reads --sig-bg, --sig-accent… with getComputedStyle, so it changes colour without its own dark-mode code.

This tutorial uses the very same trick. Press the ☾ / ☀ button at the top of this page.

9Two languages

Every sentence is written twice, on two sides of a card: English on one side, Hindi on the other. The हिंदी button doesn't translate anything. It just flips all the cards at once.

We study how humans sense and perceive the world.हम अध्ययन करते हैं कि मनुष्य दुनिया को कैसे महसूस करते और समझते हैं।
↑ a real flip card. Both sentences are in the page; CSS hides one.
<span data-l="en">We study how humans…</span>
<span data-l="hi" lang="hi">हम अध्ययन करते हैं…</span>

/* main.scss: hide the side we are not showing */
html:not([data-lang="hi"]) [data-l="hi"],
html[data-lang="hi"] [data-l="en"] { display: none !important; }

10The moving picture (S → P → IN)

Someone said “Welcome to SPIN Lab” into a microphone. A helper program measured that sound once and wrote the measurements in a notebook. The web page reads the notebook and draws the sound like a flip-book: first the wiggly line, then dots, then a colourful picture of pitches, then a map where each tiny slice of sound becomes a dot.

The timeline

The drawing follows a clock that loops every 13.6 seconds. At each moment, draw(t) asks “how far into each step are we?” and draws that much.

What the IN map really shows

  • Each dot is one 25 ms slice of sound (stepping 10 ms). Its place comes from PCA of the slice's 48-band log-mel spectrum: slices that sound alike land close together.
  • The left–right axis turned out to mean “hissy vs vowel-like”: that's why the /s/ of SPIN sits alone on the far left.
  • Colour = which word the slice belongs to. Word times were found once with a speech model (wav2vec2 phoneme forced alignment) and saved as WORDS in the script.
  • Same-word slices do not form neat groups; the lines just join each word's slices in time order.

Good manners built in

  • Pauses itself when scrolled off screen or when the tab is hidden (saves battery).
  • Reduced motion: if a visitor's computer asks for less animation, it shows still frames; the S/P/IN buttons still work.
  • ▶ Hear it restarts the clock and draws the waveform in step with the real audio.

Open the home page, press F12 for the Console, and type document.querySelector('.signal-hero').spinSeek(9000). It jumps to 9 seconds and freezes, which is how the screenshots were checked.

11“Say hey”: listening in the browser

When you press 🎤, the page asks “may I listen?”. If you say yes, your voice flows through a pipe into a little measuring box that counts how loud each pitch is, many times a second. The page draws those counts. The pipe never goes to a speaker or to the internet, so nothing is saved or sent.

This uses the browser's built-in Web Audio API. Code: initHey() in js/spin_audio.js. The top half of the little screen is the wave right now (getByteTimeDomainData); the bottom half is a spectrogram that scrolls left as new columns of loudness-per-pitch (getByteFrequencyData) arrive. The mic stops by itself after 15 seconds.

Browsers only allow the microphone on secure pages: https:// (GitHub Pages) or localhost. Opening the HTML file directly from disk won't work.

12The tiny icon (favicon)

The favicon is the tiny picture on the browser tab. It is only 16 dots wide! If you draw thin lines on such a tiny grid, they turn into grey mush. So the tiny version has just three fat bars that sit exactly on the dots.

The bars are the same waveform mark as the lab's QR codes and posters (spin_branding/), with the same indigo #1e3a8a → teal #0d6e6e gradient. scripts/make_favicon.py draws every size and writes favicon.ico (16/32/48 inside one file), images/favicon-32.png, images/apple-touch-icon.png and images/icon-512.png. _includes/head.html tells browsers where they are.

Browsers cache favicons for a long time. After changing it, check in a private window.

13Running it on your computer

Before sending the lunchboxes to the world, you open them at home to check. Your computer becomes a mini post office that only you can visit.

In the WSL Ubuntu terminal:

# the real repo (first time only: install the gems inside the repo)
cd ~/Desktop/work/research/repo/spinlabiitg.github.io
bundle config set --local path vendor/bundle
bundle install

# every time
bundle exec jekyll serve          # then open http://localhost:4000
# the redesign copy in tommy_assistant (reuses the gems above)
cd /mnt/c/Users/IITG/Documents/tommy_assistant/spinlab_website
bundle exec jekyll serve --port 4001 --force_polling   # http://localhost:4001
  • Why bundle exec? It uses the exact gem versions from Gemfile.lock, not whatever Jekyll is installed system-wide.
  • Why --force_polling? The copy lives on the Windows drive; WSL doesn't hear Windows file-change events, so Jekyll checks for changes by looking every second instead.
  • Changed _config.yml? Stop (Ctrl+C) and start again: it's only read at start-up.
  • Python scripts (scripts/*.py) run from the site folder on Windows: python scripts/make_favicon.py.

15Recipes: how do I…?

…add a news item?

Open _data/news.yml and add a card at the top (newest first). Markdown works: **bold**, *italic*, [text](link).

- date: Nov 2026
  headline: "Congratulations to Prakhar on … [paper](https://…)"

…add a new student?

Put a square-ish photo in images/teampic/ (about 400 px wide is plenty), then add a card to phd_scholars.yml, masts.yaml or bachs.yml. No photo? Leave photo out: their initials appear in a circle.

- name: New Student
  photo: new_student.jpg
  topic: Respiratory audio and machine learning
  info: One line in their own words.
  linkedin: https://www.linkedin.com/in/…        # optional: email, scholar, github, website

…move someone to Former Members?

Delete their card from the student file, then add to alumni_msc.yml / alumni_bsc.yml / alumni_visitors.yml with info (degree and years), thesis and work (where they are now).

…add a site to Showcase?

Save an 800×500 screenshot as images/showcase/<name>.jpg and add a card to _data/showcase.yml (title, url, image, kind, blurb, tags; home: true to feature it on Home; kind_hi/blurb_hi for Hindi).

…add or change a Hindi label?

Add a line to _data/i18n.yml: my_key: {en: "…", hi: "…"}, then use {% include t.html k="my_key" %} in a page or layout.

…replace the welcome recording?

  1. Save the new recording as audio/welcome_to_spinlab.wav (real voice, with the speaker's consent).
  2. Update TEXT, T0/T1 (where speech starts and ends) and the WORDS timings at the top of scripts/make_signal_data.py.
  3. Run python scripts/make_signal_data.py. It rewrites js/spin_signal_data.js and audio/welcome_web.wav.

…change the brand colours or favicon?

Edit C0, C1 in scripts/make_favicon.py and run it; update --brand-a / --brand-b in main.scss to match.

…publish?

In the real repo: git add the changed files, git commit -m "…", git push. GitHub Pages rebuilds within a minute or two. (The tommy_assistant/spinlab_website folder is a copy for trying things; changes must be brought over to the real repo to go live.)

16Leftovers to tidy someday

This house was built from another lab's house (the “Allan Lab” template from Leiden). A few of their things are still in the cupboards.

  • _config.yml still says title: The Allan Lab and description: Website of the AllanLab. They're only used when a page has no title of its own, but should become SPIN Lab.
  • Unused data files from the template or old pages: alumni_members.yml, students.yml, pictures_Leiden.yml (check pictures.md first), mtpbtplist.yml (thesis list, removed from Publications).
  • Old images in images/ (e.g. Group2015.png, STM figures, a 10 MB teampic/tjeruk.jpg) make the repo heavy (~370 MB) but aren't shown.
  • The old images/favicon.ico name is kept (now the new icon) in case anything links to it.
